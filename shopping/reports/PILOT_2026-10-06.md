# PrestaShop page-adapter pilot — 2026-10-06

> Retrospective correction: these runs verified cart execution under an expanded recommendation/substitution prompt, not full satisfaction of the original shopping request. A beanie, cap or sunglasses does not fulfill the mug need. Token comparisons excluding cached input also require checking initial cache conditions; the Sol pair had unequal initial cache hits. See [the prompt and measurement audit](PROMPT_AND_MEASUREMENT_AUDIT_2026-10-06.md).

Two concurrent `gpt-6-luna` agents at `xhigh` completed the same shopping task in separate browser sessions. Both left three correct single-quantity cart lines for review. In this single pair, the injected adapter was **16.3% slower** and used **79.2% more tokens excluding cached input**. This is a pilot observation, not a statistically established performance difference.

## Setup

- Store: PrestaShop, `http://localhost:8092/`, 530 products (30 original plus 500 filler products).
- Original products were scattered beyond the first listing page in every category. The first original product in the main listing was at position 87. Native search and sale pages remained available to both agents.
- Identical shopping and browser instructions, apart from assigned session name and artifact directory. No product IDs, recommended choices, adapter documentation, or adapter hint in either agent prompt.
- Agent A: `shop-pilot-a`, with the existing single-file script injected at document startup on this origin. Agent B: `shop-pilot-b`, without injection.
- The adapter banner was discovered in the normal page snapshot. Agent A then called `window.mcp.help()` through ordinary browser JavaScript evaluation.
- Separate nonpersistent Chrome contexts/processes; both baskets initially empty. Distinct storage markers were checked after both were set and again at final verification.
- Used standard Playwright CLI because the available in-app surface did not provide isolated context creation, and Kimi tab-group sessions shared cookies. Both agents received the same browser tool setup. No host-side shopping tool or catalog was exposed.
- No hints or interventions during the runs, no detailed agent report assignment, and no adapter changes between setup and completion.
- Temporary listing positions were restored afterward: 1,060 rows checked, zero mismatches. Carts were preserved; native platform source code was unchanged.

Adapter SHA-256: `2c8f51ab7dc87af7a68e99b0ab6c6fdc42c3a49c7cef77c18cbe1c23dbbdd00d`.

Combined usage: **168,750 tokens excluding cached input**, or 2,428,206 including cached input. Excluding cached input means `input − cached_input + output`. Reasoning tokens are already included in output and are not added again. These are telemetry counts, not a billing estimate.

Wall time is each agent’s `task_started` to `task_complete` timestamp. Setup, coordinator verification, screenshot capture, and restoration are excluded. The agents started 11.038 seconds apart and overlapped. Observed tool wait is summed call-to-output duration; the remaining wall time includes model generation, scheduling, and other overhead and must not be labeled pure reasoning time.

One executed browser CLI command counts as one interaction; one `run-code` script remains one interaction even when it performs several actions. Failed commands count. Reading snapshot files and viewing saved images do not count. B requested 21 commands, but a failed `click` prevented a trailing `&& snapshot` from executing: **20 actually executed**. Implicit snapshots returned by navigation are not separate calls.

- A: 14 evals, 2 snapshots, 2 navigations, 1 screenshot = 19.
- B: 8 scripts, 5 snapshots, 5 navigations, 1 failed click, 1 screenshot = 20.

## What happened

A successfully discovered the website-side API without prior knowledge. It used four search batches totaling 19 search queries, requested product details, and navigated to visually inspect the tee and browse accessories. It also made two avoidable failed calls: a category name where the API required a native category ID, and a cart add using a product ID no longer remembered after full-page navigation. The latter forced searches for the three exact product names before retrying. It eventually added all three, verified the cart, and opened the native cart page.

B browsed categories, initially opened a filler product, then used the native Prices drop page to find useful discounted products. It inspected product details and the tee image and searched for mug, cup, and coffee. One label-based CLI click failed; a normal role-based Playwright click worked. It batched the remaining product-page navigation and add-to-cart actions into one script.

The adapter reduced document navigations (3 versus 19 observed during the agent runs) but did not materially reduce browser interactions (19 versus 20). A also made 54 fetch requests plus 1 XHR, versus B’s 6 XHRs and no fetch requests. These are observed browser requests excluding initial page setup; they include native UI updates and do not imply 54 distinct user actions. Static resources are excluded from these figures. B’s normal navigation was fast on localhost, and both agents could batch scripts, which limits the advantage of replacing navigation alone.

The largest visible pause in A’s tool trace was roughly 48 seconds after a broad six-query search batch and before the next call. Its cause cannot be isolated from the trace. The failed cart-add recovery took about 35 seconds from the first add attempt to the successful retry call. These observations identify investigation targets; they do not prove how much time any individual fix would save.

Next changes suggested by the evidence: preserve discovered product references across same-origin navigation; make category discovery accept names or return usable category IDs clearly; reduce repeated discovery and result volume. No such changes were made during this pair.

## Exact shopping request

> I don't really know what this shop has. I'm after a red-ish T-shirt that would suit me, maybe a mug for my coffee, and some good deal on something that'll keep me warm in winter. Could you pick three things you'd recommend? I'm not sure about brands or sizes and I haven't really got a budget in mind. If they don't sell one of those things, choose a sensible alternative and explain it. Put one of each in the cart so I can look at your choices, then leave it for me. Don't buy anything.
